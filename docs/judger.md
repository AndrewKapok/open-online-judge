# 判题单元文档

## 概述

判题单元是在线评测系统的核心评测组件，以内置形式集成在核心进程中。系统启动时初始化固定数量的工作线程，由消息队列驱动评测任务，满足中小规模并发需求。

## 架构位置

- **层级**：数据层（与文件系统、SQLite、JSON 并列）
- **集成方式**：内置于核心进程（不支持扩展为独立集群）
- **驱动方式**：消息队列驱动
- **监控方式**：核心层动态跟踪

## 工作模式

### 初始化

- 系统启动时初始化判题单元
- 创建固定数量的工作线程
- 连接到消息队列
- 注册到状态跟踪模块

### 任务消费

判题单元从消息队列拉取评测任务，支持两种调度模式：

#### 1. FIFO 模式（实时评测）

- **触发条件**：提交即评测
- **分配策略**：按提交时间顺序分配判题工作线程
- **适用场景**：低延迟要求，实时反馈
- **特点**：
  - 每个提交立即进入评测队列
  - 工作线程按顺序领取任务
  - 评测完成立即更新结果

#### 2. 批量模式

- **触发条件**：缓存一定时间后集中评测
- **分组策略**：按题目分组
- **适用场景**：减少测试数据重复拷贝开销
- **特点**：
  - 同一题目的多个提交集中处理
  - 可减少测试数据加载次数
  - 提高整体吞吐量

### 内部任务分配

判题单元内部支持两种任务分配策略：

#### 1. 轮询分配

- 工作线程按轮询方式领取任务
- 负载均衡，适合题目分布均匀的场景

#### 2. 固定题目分配

- 固定由一个工作线程负责同一题目
- 评测完成后再协助其他题目
- 适合测试数据较大的场景（减少重复加载）

## 评测流程

### 1. 任务接收

```
消息队列 → 判题单元拉取任务 → 解析任务参数
```

**任务参数包括**：

- 提交 ID
- 用户 ID
- 题目 ID
- 竞赛 ID
- 代码路径
- 编程语言
- 题目配置（时空限制等）

### 2. 代码编译

根据编程语言执行相应的编译命令：

- **C/C++**：使用 gcc/g++ 编译
- **Java**：使用 javac 编译
- **Python**：无需编译（解释执行）
- **其他语言**：根据配置执行相应编译命令

**编译参数**从题目配置 `config.json` 中读取。

### 3. 测试用例执行

对每个测试点执行以下操作：

1. **读取测试数据**
   - 从文件系统读取 `.in` 文件（输入）
   - 从文件系统读取 `.out` 文件（期望输出）
2. **执行程序**
   - 运行编译后的程序
   - 输入重定向到 `.in` 文件
   - 捕获程序输出
3. **结果比对**
   - 将程序输出与 `.out` 文件比对
   - 支持多种比对方式（精确匹配、特殊判题等）
4. **资源统计**
   - 记录执行时间
   - 记录内存使用
   - 检查是否超限

### 4. 结果回写

- 将每个测试点的结果写入提交记录
- 更新 SQLite 数据库中的提交状态
- 更新排行榜（如需要）
- 通知核心层任务完成

## 支持的评测状态

### 整体状态

- **Pending**：等待评测
- **Running**：正在评测
- **Accepted (AC)**：通过
- **Wrong Answer (WA)**：答案错误
- **Time Limit Exceeded (TLE)**：超时
- **Memory Limit Exceeded (MLE)**：超内存
- **Runtime Error (RE)**：运行时错误
- **Compilation Error (CE)**：编译错误
- **System Error (SE)**：系统错误

### 测试点状态

每个测试点包含：

- **状态**：AC/WA/TLE/MLE/RE 等
- **得分**：该测试点得分
- **执行时间**：毫秒
- **内存使用**：KB 或 MB

## 配置文件

### config.json 结构

```json
{
  "problem_id": 1,
  "contest_id": 1,
  "time_limit": 1000,
  "memory_limit": 256,
  "test_cases": 10,
  "languages": ["C", "C++", "Java", "Python3"],
  "compiler_flags": {
    "C": "-O2 -std=c99",
    "C++": "-O2 -std=c++17"
  },
  "comparator": "default",
  "input_output": {
    "type": "stdio",
    "input_file": null,
    "output_file": null
  }
}
```

### 配置说明

| 字段                 | 说明       | 示例                        |
| ------------------ | -------- | ------------------------- |
| time\_limit        | 时间限制（毫秒） | 1000                      |
| memory\_limit      | 内存限制（MB） | 256                       |
| test\_cases        | 测试点数量    | 10                        |
| languages          | 支持的语言列表  | \["C", "C++", "Python3"]  |
| compiler\_flags    | 编译参数     | {"C++": "-O2 -std=c++17"} |
| comparator         | 比对方式     | "default" 或自定义            |
| input\_output.type | 输入输出方式   | "stdio" 或 "file"          |

## 监控与状态跟踪

### 状态信息

判题单元的运行状态由核心层动态跟踪：

- **工作线程状态**：空闲/评测中
- **当前任务**：正在评测的提交 ID
- **任务进度**：已完成测试点数量 / 总测试点数量
- **心跳信息**：最后活跃时间

### 更新机制

- 判题单元定期发送心跳
- 状态变更时立即更新
- 超时未更新视为异常

### 查询接口

通过 CLI 可查询：

- 判题负载情况
- 队列状态
- 单个任务进度
- 工作线程状态

## 管理操作

### CLI 管理命令

#### 查看判题状态

```
oj-cli judger-status
```

显示所有工作线程的状态和当前任务。

#### 查看队列状态

```
oj-cli queue-status
```

显示消息队列中的任务数量和等待时间。

#### 查看任务进度

```
oj-cli task-progress --submission-id 123
```

显示指定提交的评测进度。

#### 取消任务

```
oj-cli cancel-task --submission-id 123
```

取消队列中指定的评测任务。

#### 切换评测模式

```
oj-cli set-judge-mode --mode fifo
oj-cli set-judge-mode --mode batch
```

在 FIFO 和批量模式之间切换。

## 与其他组件的交互

### 与核心逻辑层

- 接收评测任务
- 回写评测结果
- 更新工作状态和心跳
- 通过 Unix Domain Socket 通信

### 与文件系统

- 读取题目配置（config.json）
- 读取测试数据（testdata/*.in, testdata/*.out）
- 读取用户代码
- 写入编译产物

### 与 SQLite 数据库

- 更新提交记录
- 更新测试点状态
- 更新排名信息

## 性能优化

### 批量评测优化

- 同一题目集中处理
- 减少测试数据重复加载
- 提高缓存命中率

### 编译优化

- 复用编译产物（如可能）
- 并行编译多个提交
- 优化编译参数

### 执行优化

- 预加载测试数据
- 减少进程创建时间
